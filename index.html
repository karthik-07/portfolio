01 / FLAGSHIP PROJECT

What Broke? — the one I use myself.

A local Linux forensics CLI that answers the question every developer asks after an update: what changed before this started failing?

ACTIVE BUILDPYTHON · ARCH LINUX · SYSTEMD · PACMAN

What Broke?

Linux system-change forensics for the moment when everything worked yesterday.

What Broke? started after I got tired of comparing journalctl output and Pacman package history by hand on my own Arch Linux machine. The CLI compares systemd journal failures across boots, spots newly observed signatures, and shows the package changes that came before them.

05 / ABOUT

I care more about the reasoning layer than the demo layer.

My background spans software development, cloud computing, Linux, and cybersecurity. I’m usually happiest when there is something concrete to untangle: a broken system, an awkward workflow, a query that needs structure, or a signal that needs alignment.

I prefer small, explainable systems with clear boundaries over unnecessary complexity. If a simpler approach works, I would rather understand it deeply than hide the problem behind another layer.

WHY I BUILD SIDE PROJECTS

Most of them start because something annoyed me enough to investigate it. What Broke? came from debugging my own Linux machine. I’d rather turn that frustration into a tool than solve the same problem twice.
